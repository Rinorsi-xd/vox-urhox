# 判定原理

## 问题本质

UrhoX 跨 D3D 风格（纹理 v=0 在上）与 GL 风格（v=0 在下）多个后端运行。引擎在大多数路径上已经抹平差异，但以下环节在部分设备 / runtime 版本上会出现"上下镜像"：

| 怪癖 | 含义 | 判定位 |
|------|------|-------|
| shown | 相机渲染的 RT 经 `nvgCreateVideo` + `nvgImagePattern` 显示时上下颠倒 | 方向图左右两列不同 |
| sampled | 相机渲染的 RT 在 shader 中 `texture()` 采样时行序颠倒 | 哨兵 v=0.25 处读到蓝色 |
| nvgSampled | NanoVG 渲染的 RT 在 shader 中采样时上下颠倒 | 方向图左列 v=0.1875 处读到蓝色 |

三者互相独立：同一设备可能只有其中一种，也可能有两种。三者都是**纯上下镜像**，所以组合时用异或（`abs(a-b)`）。

已观察到不一致的环境：桌面 WebGPU、手机 WebGPU、两款手机 WebGL；桌面原生通常全为 0。**这张表会随 runtime 更新变化**——这正是必须现场测量的原因。

## 方向图（8×8，NanoVG 渲染目标）

```
 x: 0    4    8
    +----+----+  y=0
    | 红 | 源 |       左列：NanoVG 直接画的参照（红上蓝下）
    |    | 上半|       右列：被测 RT 的"显示出来的上半/下半"，
    +----+----+  y=4         通过与真实显示完全相同的 nvgImagePattern 链路画进来
    | 蓝 | 源 |
    |    | 下半|
    +----+----+  y=8
```

- 采样点：左 `(0.1875, 0.1875)`、右 `(0.8125, 0.1875)`，即块中心，避开 AA 晕边。
- **shown = 左右红色分量不同**。关键性质：不论 shader 读这张图时行序是否颠倒，左右两列一起颠倒，比较结果不变——所以 shown 判定本身不受 nvgSampled 怪癖影响。
- **nvgSampled = 左列读到蓝色**。左列是 NanoVG 画的"红在上"，shader 读到蓝说明 NanoVG RT 在 shader 中是倒的。
- 有效性门槛：`step(0.5, l.a) * step(0.5, r.a)`。方向图还没画过时是全透明 → 判定为 0 → 不翻。

右列的"源"有两种：

1. **实时内容自带角标记**（路径 A，如通讯立绘）：内容 shader 在 RT 左上角 2×2 texel 画红、左下角画蓝，显示时用 scissor 裁掉；`DrawCorner` 把显示出来的角放大画进方向图。
2. **哨兵**（无实时内容时）：一张 8×8 相机 RT，用与内容相同的四边形、正交相机、渲染路径，shader 输出上半红下半蓝。

## 哨兵（8×8，相机渲染目标）

- `OrientSentinel.shader`：`top = step(0.5, 1.0 - UV.y)`，上半红、下半蓝（以内容四边形的 UV 约定为准：v=0 在上）。
- **sampled = 在 shader 中读 `(0.5, 0.25)` 是蓝色**（`step(0.5,a) * step(r,b)`）。
- 同时作为方向图右列的源，提供 shown。
- `SURFACE_MANUALUPDATE` + 每次 `Request()` 时 `QueueUpdate()`；创建后 2 帧才认为就绪，之后方向图才用它。

## 为什么能扛住 runtime 更新

- 没有任何一行代码依赖"某平台应该是什么方向"。runtime 修好了某个翻转 → 测量值变 0 → 不再翻；runtime 引入新翻转 → 测量值变 1 → 自动翻。
- 测量链路与内容链路共用同一套 API 调用（同一个 `nvgCreateVideo`/`nvgImagePattern`、同一 `SetSurfaceTexture` 采样、同一渲染路径 XML），runtime 改动不可能只影响其一而不影响另一个。
- 判定在 GPU 每帧（或每次拷贝）执行，没有缓存到 Lua 变量的"方向结论"，不存在"启动时测一次之后过期"的问题。
- 失败一律落到"不翻"，最坏情况等同于没有这套机制，而不是错误地翻倒。

**唯一会失效的情形**：runtime 引入了新的、不属于上述三种的变换（如左右镜像、90° 旋转）或新的显示链路。对策：自检场景里有左上角绿点，可同时看出左右镜像；新链路按 `patterns.md` 归类，如果归不进四种路径，就仿照方向图的做法为它加一个"参照 vs 被测"的对照列。

## 引擎文档冲突说明

`engine-docs/recipes/scene-to-nanovg.md` 写"`nvgCreateVideo` 已处理预览纹理的上下方向，不需要额外翻转 Y"。这在多数平台成立，但本项目在部分手机 WebGL / WebGPU 上实测不成立。按本工作流做的检测在"已处理"的平台上测得 0，不会翻，因此与文档并不冲突：**两种情况都能正确显示**。
