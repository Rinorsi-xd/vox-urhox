# 局内战斗：手机 WebGL 卡顿与操控优化分析（2026-10-20）

> 范围：4v4 / 3v3 局内战斗。代码基线 `01362da2`（含引导修复前）。只做分析，未改代码。
> 标注「实测」的来自本机或仓库已有证据；标注「估算」的是推断，需真机确认。

## 0. 一句话结论

手机卡是**CPU 和 GPU 两头都超预算**：

- CPU：物理/AI/武器是固定 60 Hz 步进，手机限帧 30，每帧至少跑 2 步、负载高时跑满 3 步；每步产生约 1 MB Lua 垃圾，GC 一次回收十几 MB 就是一次明显卡顿。
- GPU：手机 WebGL 走「手机档」渲染，3D 画面按**物理分辨率全尺寸**画（无渲染缩放），地图/地形/护盾着色器很重，画面完全受像素填充率限制。
- 操控：触屏转向本身没问题；**瞄准辅助有 4 个硬伤**（压低就失效、快目标反而难吸、只拉位置不跟速度、不锁目标乱跳），手机低帧时更明显。

最值得先做的三件事：**渲染分辨率缩放（手机默认 ~70%）**、**AI 思考错峰 + 战斗期 GC 策略 / 热点去分配**、**触屏辅助瞄准四项修正**。

### 1.2 仓库已有证据（摘要）

- 无头原生 4v4（`docs/migration/evidence/native-cpu-fa51051c`）：每步均值 15 ms，P99 64 ms；**每步新建约 1 MB Lua 对象**；最长的 8 个步里每次都回收了 16–18 MB → 卡顿与 GC 对齐。
- 车辆零件掉落/修复触发整车重建（`VehicleSpec.Build` 30 秒 68 次，单次约 3.7 ms，`CarUnit.Flush` 最大 55 ms）。
- 桌面 Chrome WebGL：局内帧中位 50–104 ms，95% 以上 CPU 在 WASM 内无法再细分。
- 渲染 A/B（`.tmp/render-ab-20261019`，冻结同一帧）：分辨率 70% → GPU −30%；50% → −45~48%；关泛光 −18%；关阴影 GPU 只省 ~2 ms 但批次 −36%、提交 CPU −1 ms；关灯/关特效 ≈ 0。
- **估算**：手机 DPR 2.5–3 全分辨率 2.4–3.2 MP，GPU 填充比 M1 慢 3–5 倍；Lua 在手机 WASM 比 M1 原生慢数倍 → 每帧 75–150 ms，即 7–13 FPS + 慢动作，与「很卡」吻合。

> 注：本机 macOS runtime 的 `GetPlatform()` 返回 `macOS`，不在 `IsDesktopPlatform()` 的白名单里（只认 `Mac`），所以本机采样走的就是手机/Web 同一条代码路径，可直接参考。

## 2. 性能优化建议

### P0（收益最大，建议先做）

**P0-1 手机渲染分辨率缩放（GPU，收益高，风险中）**
- 现状：手机/Web 分支直接 `Viewport:new(scene,camera)`（`render/GraphicsSettings.lua:99`），没有缩放；桌面才有 `AdaptiveResolution`（`render/AdaptiveResolution.lua:31`，按 CSS 像素封顶）。
- 做法：场景渲染到缩放后的离屏目标再放大，UI 保持原分辨率。可复用 `FilterGraph.lua`（场景源 + 一个拷贝/色调映射 pass）和 `AdaptiveResolution.Size`。触屏默认按 CSS 像素 × 0.7，设置里给「渲染精度 50/70/85/100%」。
- 预期：GPU −30~45%（A/B 实测比例）。
- 风险：WebGL 下半浮点渲染目标 / MSAA 目标支持需真机确认（`FilterGraph.lua:26-28` 已有单采样回退）。

**P0-2 AI 思考错峰 + 射线预算（CPU 尖峰，收益高，风险低）**
- 现状：所有 AI `nextThink=0`（`combat/EnemyDriver.lua:14`），间隔 0.2 s（`EnemyDriverMath.lua:3`）→ 7 个 AI 在同一步一起思考。思考时射线极多：`T.Strafe` 最坏 ~250 条，狙击手找位置对 125–190 m 外每个导航点各打一条 150 m 射线（`EnemyDriverThink.lua:72-77`）。实测 `EnemyDriver.Step` P95 4 ms / 最大 76 ms，思考步垃圾 925 KB。
- 做法：`nextThink = index * 0.2 / N` 错开；`MatchTarget` 0.5 s 缓存同样错开；每步全局射线预算；`Direct/Visible` 结果按网格格子缓存 0.5 s。
- 风险：会改变与 H5 回放夹具的确定性对齐（玩法上无感）。

**P0-3 战斗期 GC 策略 + 热点去分配（CPU 卡顿，收益高，风险低~中）**
- 现状：每步 ~1 MB 垃圾 ≈ 60 MB/s；战斗中没有任何 GC 调参。主要来源：
  - `core/Math3.lua:4-40` 每个运算返回新表，全局使用；
  - `physics/Body.lua:142-145` 每次 `translation()/rotation()/linvel()` 新建表；
  - `drive/Vehicle.lua:170-174,200-201`、`drive/RaySuspension.lua:49-128`、`combat/BattleController.lua:152,170-171`、`combat/EnemyDriver.lua:79-94`、`physics/Space.lua:39-46`、`render/CombatEffects.lua:281-347`；
  - 辅助瞄准对敌车每个体素格新建约 5 个小表（`combat/AimAssist.lua:22-31`）。
- 做法：① 进战斗切增量 GC 并调 pause/stepmul，或每帧小步 `collectgarbage('step', n)` 均摊（需真机比对）；② 上述路径改为复用 scratch 表 / 标量数学（`VehicleRay` 已是先例）。
- 风险：复用表的别名 bug；逐处改、逐处测。

### P1

**P1-1 泛光 / 自动曝光可关（GPU，中高）**：手机档强制 `Bloom Enable=true` 只为保留色调映射（`GraphicsSettings.lua:71`），自动曝光只用来输出固定曝光（`render/FixedExposure.lua`）。给「低」档关泛光、固定曝光不走亮度链。A/B 关泛光 −18% GPU。风险：关泛光可能连带丢色调映射，需目测。

**P1-2 地图 / 地形 / 护盾着色器手机变体（GPU，高·估算）**
- `assets/Shaders/BLGL/Crater/Map.shaderinc`：`mFbm` 最多 8 层 3D 噪声，沙地块每面 3 次 fbm，全部 `cull_disabled`。
- `Crater/Terrain.shader`：近处每像素 20–30 次数组纹理采样（双重去平铺 + 双三平面）。
- `Crater/Shield.shader`：每像素 2 次 voronoi（~108 次 hash），出生点就在护盾内，开局整屏都在付费（A/B 机位在护盾外，没测到）。
- 做法：噪声烘成贴图、强制单采样、去掉细节层、闭合网格改 `cull_back`；护盾从内部看淡出或用贴图版。

**P1-3 零件损坏 / 修复不再整车重建（CPU 尖峰，高，风险中）**：`combat/CarUnit.lua:364-405` 每次重建刚体、全部碰撞形状、凸包与惯量探测；脱战修复每 0.5 s 修一块又触发一次（`combat/BattleObjectives.lua:154-164`）。做法：保留刚体只增删形状（Disable/EnableMassUpdate 包住）；修复合批（如每 2 s 修几块）；`JoinedMesh` 分块只重建受影响块。

**P1-4 射线对每辆车的预剔除（CPU，中，风险低）**：`TrackWorld:CastRay`（`drive/TrackWorld.lua:99-108`）每条射线都对所有活车做 Lua 级命中；机甲每步清空包围盒缓存导致首条射线就跑一遍 6 腿 IK（`drive/LegHitboxes.lua:41-47`）。做法：先做车包围球剔除；腿用按伸展范围的保守包围盒；纯静态查询用带层掩码的单命中射线。

**P1-5 降低每帧物理步数上限（CPU，中，风险低）**：手机 `maxSimSteps=3 → 2`（`render/Quality.lua:6`）。最坏帧上限降到 2/3，代价是更早进入慢动作。可作为止血手段。

**P1-6 阴影手机档（CPU 提交，中，风险低）**：手机 2 级级联、缩短距离，地图 `shadowDistance≈40`，AI 车只在近处投影。A/B：关阴影批次 −36%。

### P2

- **特效改 GPU 展开**：`render/EffectBatch.lua:23-62` 每个四边形 ~25 次绑定调用 + 5 个原生对象；`render/WeaponEffects.lua:170-196` 每帧扫全部零件拼 640 段电弧。参考 `CraterDust` 的 GPU 化做法；先加视锥/距离剔除。
- **`ObjectiveView` 别在物理步里重建**（`render/ObjectiveView.lua:116-172`，每秒 10 次重建上万顶点）：网格建一次，进度/颜色走材质参数，挪到每帧更新。
- **碰撞回调合并**：每车两个 Lua `NodeCollision` 回调各自拷贝接触点（`drive/ObstacleSlide.lua`、`audio/CollisionAudio.lua`），合并为一个并提前丢弃平地接触；贴墙磨蹭时 `ObstacleSlide.Clear` 可能每步跑很多次凸体扫掠。
- **残骸池化**：`combat/Debris.lua` 每块新建节点+刚体+视图（上限 60、寿命 5 s），手机合并小碎块、分帧生成、缩短寿命。
- **玻璃不读屏幕纹理**（`VoxGlass.shader:8` + 9 次模糊采样）、**载具着色器去掉仅机库倒影才需要的 `discard`**（会关掉移动 GPU 的 early-Z）。
- **小地图 10 Hz 且有变化才重绘**（`ui/MatchMinimap.lua:69-70`，现在约每帧重画）。
- **画面设置补齐手机选项**：渲染精度、阴影开关、泛光开关；目前手机「高」和「中」实际等价。

## 3. 操控：灵敏度与索敌

### 3.1 现状

- 触屏转向：线性、无平滑、无加速、与帧率无关（`controls/TouchGestures.lua:41-42`，`ChaseState.lua:14-16`）。一屏高横拖 ≈ 82.5° × 灵敏度；纵向固定为横向的 83%；灵敏度只有 4 档（0.6/1/1.5/2.2）；开镜按武器缩放；PC 没有灵敏度设置。
- 地面载具最多只能**抬头约 24°**（`ChaseState.lua:24-25`），打飞机和高处机甲很吃力。
- 辅助瞄准（`combat/AimAssist.lua` + `controls/DriveAim.lua`）：只有机枪 / 激光有；触屏范围放大 2.2 倍（机枪 6.6°，激光 4.4°）；**狙击 / 导弹 / 钻头没有**；每帧重选，无粘滞；无提前量；可见性从镜头而非枪口判断。

### 3.2 主要问题（按影响）

| # | 问题 | 位置 | 影响 |
|---|---|---|---|
| 1 | **准星稍低就失效**：射线先打到敌人脚前地面，只认命中点 +2 m 以内的格子 → 候选全被丢。追尾镜头默认俯视，手机上最常见 | `AimAssist.lua:13,28` | 高 |
| 2 | **快目标反而难吸**：范围按目标绝对横向速度缩小（30 m 外 15 m/s 横穿，6.6° → 约 3.6°，估算） | `AimAssist.lua:19-20` | 高 |
| 3 | **只拉位置不跟速度**：拉力时间常数 ~0.33 s，跟横穿目标会落后 ~10°（估算）直接出圈；准星一碰车身就停拉 → 在车身边缘抖 | `DriveAim.lua:30-36` | 高 |
| 4 | **不锁目标**：每帧按最小角度重选，在多个敌人、同车多个零件间跳；目标框闪烁并重播动画 | `AimAssist.lua:38`，`ReticleTarget.lua:20` | 高 |
| 5 | 拉力与意图无关：开车时也拉镜头，反向拖动时还在拉；飞机「指向」模式下连机身一起被拉 | `DriveAim.lua:30` | 中 |
| 6 | 减速在整个范围内都是 0.6，跟横穿和甩枪都更难（PC 也受影响） | `DriveAim.lua:28` | 中 |

| 8 | 从镜头判可见：低掩体挡住炮塔但镜头看得见 → 锁上打不到 | `AimAssist.lua:40` | 中 |

| 11 | 自动开火不看炮塔角度 / 是否被挡；导弹锁定框在触屏上没放大且不判可见 | `DriveAim.lua:39-41`，`MissileWeapons.lua:57` | 低 |
| 12 | 第二根手指落在屏幕上会把转向变成缩放，且缩放会保留 | `TouchGestures.lua:34-39` | 低 |

### 3.3 改进建议

**P0（触屏专用）**
1. **压低不失效**：触屏下准星射线打到的不是车时，按「无命中」处理，不再用 `near+2` 过滤；真实掩体仍由可见性射线挡掉。一处改动。
2. **跟踪而不是只拉位置**：加入目标相对角速度 `ω = (dir × (v目标 − v自己)) / 距离`，每帧 `yaw += ω_yaw × 0.6 × s(θ) × dt`，位置拉力改为 `(1 − e^(−4dt)) × s(θ)` 并限 20°/s；`s(θ) = 1 − smoothstep(0.4·cone, cone, θ)`；碰到车身后继续跟踪；只在拖动或开火（及之后 0.3 s）时生效；反向快速拖动（>150 px/s）时 0.25 s 内辅助降到 25%。
3. **粘滞目标**：记住 `{目标, 零件, 本地坐标点}`，每帧只验证一条射线；在 1.5 倍范围内、存活且可见就保持（0.2 s 宽限）；新目标角度 < 当前 0.6 倍且持续 0.15 s 才切换；瞄点取最近格与零件中心的中点而非边缘格；完整搜索降到 15 Hz。预计辅助 CPU −60~90%（估算）。
4. **快目标不缩范围**：用相对速度，范围系数改为 `clamp(1 + 0.3 × min(1, ω/0.6), 1, 1.3)`（快目标略放大），至少设 0.8 下限。

**P1**
5. 机枪提前量：`t = 距离/260`，`P' = P + v相对 × t` 迭代两次，上限 1.5 倍范围；只作用于炮塔瞄点，可选画个小提前量标记。
6. 减速分方向：范围边缘 0.75、车身上 0.6，只减「远离目标」方向的分量；拖动 >1200 px/s 不减速（甩枪）。
7. 设置项：灵敏度滑条 0.4–3.0（步进 0.1）、纵横比（默认 0.83）、开镜倍率 0.5–1.5、Y 轴反转；PC 鼠标灵敏度。
8. 瞄准射线用本帧姿态并在加镜头震动之前取，去掉一帧延迟和震动带枪。
9. 只对选中的目标从枪口补一条可见性射线。
10. 地面载具抬头上限到约 40°，机甲约 50°（`minY` 地面保护需验证）。
11. 辅助瞄准格子遍历改标量数学、先按零件包围球剔除、缓存 `bp:List()`。
12. 准星与反馈在触屏上加粗放大：线宽 ≥ 1.5–2 CSS px，命中标记放大 1.3 倍、持续 0.4 s，「辅助生效」时准星变色收紧；名牌 / 血条文字 ≥ 9–10 CSS px。

**P2**
- 自动开火要求炮塔对准且未被挡、对准 0.1 s 后才开火；开镜和狙击（蓄满即发）也支持。
- 触屏导弹锁定框放大 1.4 倍、锁定 1.5 s、加可见性判断。
- 局内关掉双指缩放或提高触发阈值；加触屏跳点过滤。
- 缓动统一用 `1 − e^(−k·dt)`。
- 狙击触屏只给减速不拉（范围 1.5°，减速 0.5）。

## 4. 建议的落地顺序

1. **第一批（止血，1–2 天）**：P0-1 渲染缩放、P0-2 AI 错峰、P1-5 手机步数上限 2、P1-1 低档关泛光、触屏辅助 P0-1（压低不失效）与 P0-4（快目标不缩）。
2. **第二批**：P0-3 GC 策略 + 去分配（逐模块）、P1-3 零件不整车重建、触屏辅助 P0-2/P0-3（跟踪 + 粘滞，顺带降 CPU）。
3. **第三批**：着色器手机变体、特效 GPU 化、操控设置项与准星反馈。

## 5. 需要真机确认的

- 手机浏览器 / TapTap WebGL 下：`graphics:GetWidth/GetHeight/GetDPR/GetMultiSample`，日志里的 `[AA] backbuffer multiSample=`。
- 是否支持实例化和半浮点渲染目标（影响 P0-1 与批次数）。
- 局内每帧物理步数、P95/P99 帧时间、`droppedTime`（慢动作程度）。可在设置「调试 / 性能」里开性能面板，或 `-vox-perf=1`。
- 出生点在护盾内时的帧时间；有玻璃车、推进器车在画面时的帧时间。
- 每项改动前后：同一局 30 / 20 FPS 下的命中率、准星在目标上的时间占比。
