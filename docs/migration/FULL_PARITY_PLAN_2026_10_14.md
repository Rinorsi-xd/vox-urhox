## 1. 每条如何验收

以下每行是独立验收项，全部初始为 `[ ]`。状态列只描述当前静态审计，不代表执行状态。

共 16 组、138 个主验收项：Z6/U10/H7/E10/R7/P14/C8/W9/M8/B8/S9/N7/L8/A9/D8/Q10。一个主项含多个车型、事件或子条件时，执行记录必须拆出逐个子结果，全部适用条件通过才能勾选该主项，不能用一台车或一张截图代表全项。

每条证据至少记录：ID、源提交/文件哈希、目标提交和未提交 diff 指纹、构建 manifest、平台/设备/浏览器、分辨率/DPR、初始蓝图/存档/随机种子、步骤、期待值、实测值、适用的功能/视觉/手感/性能结果、证据路径。证据建议位于 `docs/migration/evidence/full-parity/<manifest>/<ID>/`，避免覆盖旧失败报告。

关闭规则：修正 -> 自动对照 -> 真实入口操作 -> 同状态截图/视频 -> 检查关联回归 -> 更新该 ID。只测了逻辑，视觉/手感仍待验时保持未勾选。源占位项可以按“与源占位等价”关闭，不能按新功能完成关闭。

## 19. 最终签收和报告格式

所有ID按以下结构填写，初始功能/视觉/手感/性能字段均为 `NOT_RUN`；不适用要写原因，不能空着。

```text
ID:
当前状态: OPEN / FAIL / PARTIAL / PASS
源提交 / 源文件哈希:
目标提交 / 未提交变更指纹 / manifest:
设备 / OS / 浏览器 / viewport / DPR / 质量档:
初始蓝图 / 存档 / 随机种子:
复现步骤:
源期待值:
目标实测值:
功能 / 视觉 / 手感 / 性能: NOT_RUN / FAIL / PASS / N/A(原因)
对照截图 / 连续视频 / 音频 / 日志 / 自动报告:
依赖ID与回归范围:
剩余差异 / 阻塞:
人工验收记录:
```

最终必须交付：源入口/事件/资源对照账本、全部ID结果、PC和横屏页面对照册、各移动方式驾驶对照、全模式完整录像、真实账号刷新恢复、真机持续性能、错误/失败/限制清单、可运行构建身份与回退点。

不可签收条件：有空回调/占位代替源已有系统；有有效零件/模型缺失；有功能但明显不同的字体/HUD/操控；有未关闭的进场/保存/地图/音频阻塞；只用旧构建PASS；只用电脑模拟移动端；未完成项未登记。

没有把本计划中任何功能预先勾选。G0 中通过的子检查不能代替整个主项通过；以执行报告为准。今后发现的新可达源功能追加ID、依赖和验收步骤，不能把本清单数量作为需求上限。
