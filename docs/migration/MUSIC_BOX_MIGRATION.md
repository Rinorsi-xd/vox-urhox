# 音乐盒迁移记录

## 原版依据

来源只使用 H5 分支 `2026-10-13` 的冻结提交 `90862445074e7e146da900037979ad97899ecf6c`。逐文件来源和哈希见 `music-box-source.json`，原页面 DOM 几何与 computed style 见 `evidence/source-music-box.json`。

原实现为 `shared/ui/musicBox.js`、`shared/css/music-box.css` 与 `shared/audio/`。使用原字体、图标路径、卡带图、背景纹理、颜色、切角、曲目顺序和横屏断点；不添加新按钮、说明文字或替代美术。

## 已接入

- 主页原入口及音乐盒主体。PC 880×620；840×378 为 720×338；800×450 为 720×410；1024×768 为 880×620。音乐盒在 H5 中不属于缩放的主页画布，因此按真实 CSS 视口测量，再换算到 UrhoX UI 坐标。
- 六组筛选、英文/中文搜索、收藏和空状态、滚动/定位当前、关闭、Escape、Tab 焦点及播放模式菜单。
- 原 13 首正式 MP3、播放/暂停、seek、上一首超过三秒重播、随机袋、顺序播放、单曲循环、音量和静音恢复。音量使用原 `10^(-36*(1-v)/20) × .8`。
- 独立音频 Scene 跨大厅场景存活。按需下载、过时回调拒绝、最多两份压缩 Sound、2.4 秒 smoothstep 淡化、切换结束释放旧资源。原生实测 181.767 秒曲目保持压缩，约 4.36 MB。
- 关闭音乐盒后保留所选曲目，播完再恢复场景曲目；关闭与销毁时解除输入拦截、取消下载观察。

## 验证

原生功能检查 32/32，局外回归 98/98。原生窗口尺寸未按启动参数改变，因此手机布局只使用实际浏览器视口检查。

四端 Web 检查按真实 DPR 运行，每端 29 项断言通过：对照原 H5 的十个实测矩形，并验证打开、搜索、筛选、暂停时播放位置、模式菜单、音量、关闭重开和按访问下载。完整报告保留引擎启动的 `Strings/RenderBlockingTypes.json` resolver 错误，均为 FAIL，不能称为整份报告零错误。平板另记录一条截断的 QA 状态日志并重取完整状态。截图人工核对不等于逐像素一致性或真机性能通过。

复验入口：`tools/migration/verify-music-box.ps1`、`check-music-box-web.cjs`、`verify-source-assets.mjs`。原素材与 DOM 重采集入口为 `import-music-box.cjs`，仅从冻结快照读取。

## 尚未达到原版的部分

- 原版通过 Web Audio Analyser 绘制实时 FFT。公开 Lua Audio/SoundSource 没有 PCM/FFT tap，`MixOutput` 不支持 Lua；目前绘制原静止 2px 基线，播放时没有真实频谱。
- 原生收藏/设置使用现有双代存档；Web 跨刷新持久化尚未通过，不能等同原版 localStorage。
- 原 Windows 系统字体在原生端可就地读取；Web 使用已有 MiSans fallback，未证明跨平台像素一致。没有把 Windows 系统字体复制进发布包。
- 悬停颜色过渡和部分阴影仍未完整复刻。淡化由 Lua 帧更新驱动，未验证卡帧时与原 AudioContext 时钟完全一致。
- 原版 740×333 与 760×428 下的列表高度实测为 0，播放区域发生遮挡。保留原截图作为源缺陷证据；目标端 `max-width:760px` 分支仍待处理，不能声称所有横屏尺寸通过。
- 大厅光照、反射、相机和顶部涂装页签的缺口属于整套局外迁移，不能用音乐盒功能检查掩盖。

当前是原音乐盒的实际迁移实现，尚不是完整一比一验收通过，也未发布或提审 Maker。
