# 八车分配归因与 VehicleRay 候选实测

日期：2026-10-17。结论：**候选未证明 CPU 收益，拒绝合入生产，未宣称 FPS 提升。**

本轮不是重开 G0。源基线仍为 H5 10/15 `b2760649`、目标 `1016/f94827b2`；实际测量输入是冻结 `fd9747b4` / 指纹 `9058acb9c6aa6a3b692ddffaf7bee5714df77f849a336d8e02419d8f09a3557e`。候选不包含随后新增的库存滚动和 Convoy 顺序修复。548 生产模块的 SHA 由夹具 identity 保留。

## 1. 本轮确切回答

- 找到了持续模拟中的大量 Lua 临时对象分配，不能把所有卡顿都归给 AI 或 GPU。
- 在实际八车、悬挂、腿部、武器、射线和 Bullet 的有界单步记录中，每固定步净新增 `643.696 KiB`。`TrackWorld.CastRay` 是本次记录中最大的独占分配范围，`89.751 KiB/步`；其内部尚包含未单独包装的 `VehicleRay.Cast`，这不是已经测得的某个 Cylinder CPU 耗时。
- 针对该路径准备了只消除 Cylinder 临时向量表的等价候选，随后运行正常自动 GC 的 ABBA。原版和候选平均都是 `3.6625 ms/步`，没有收益信号。保留原版。
- 仍未证明全游戏、Web 或骁龙 845/TapTap 持续 30 FPS。分配诊断、Native 模拟基准、实际 Web 帧时间是三个不同证据边界。

## 2. 分配诊断：两次实际 Native 记录

使用八份真实对局捕获蓝图，共 1275 零件；一台手动低速前进并持续请求开火，七台实际 EnemyDriver，真实陨坑碰撞和 Bullet。初始化地图物理体为 479 个。固定随机种子 1016，120 步正常 GC 预热；随后记录八个单步，单步之间正常自动 GC。

每段停止 GC 仅覆盖一个同步固定步；16 MiB/250 ms 上限在被包装函数出口检查。它不能中断一个尚未返回的引擎调用。所有这种采样的耗时均标为 `INVALID_FOR_PERFORMANCE`，不用于 CPU 或 FPS 收益。

两次记录均完成八个采样，采样内七次实际发射；进程退出码 0，Native ERROR 为 0，GC 及包装恢复通过。加细武器子范围后，总分配仍精确为 `643.696 KiB/步`。

| 范围 | 独占分配 KiB/步 | 解释 |
| --- | ---: | --- |
| TrackWorld.CastRay | 89.751 | 内含未包装的 VehicleRay.Cast；44 次调用的八步合计 |
| Space.Raycast | 55.102 | 917 次调用的八步合计 |
| RaySuspension.Apply | 约 43.97 | 悬挂施力范围 |
| HoverControl | 约 37.19 | 悬浮控制范围 |
| 车辆 body.rotation | 约 36.60 | 所有车辆包装方法汇总 |
| WeaponSystem.Aim | 12.813 | 80 次调用的八步合计 |
| WeaponSystem.Integrate 本体 | 3.505 | 已扣除记录到的射线等子调用 |

`Vehicle.Step` 含子调用约 `52.775 KiB/车/调用`。这是包含量，不能与上述独占量重复相加。粗分时 WeaponSystem.Step 看似较大；细分后其本体独占为 0，主要分配实际落在子路径。未执行的特效方法有显式清单，不能据此判断完整渲染特效成本。

这证明分配发生在哪里，不证明回收停顿持续了多久，也不证明把某处表去掉就一定提帧。

## 3. 唯一候选与行为验证

生产 `VehicleRay.lua` SHA：`f15cd3d58efd061e22bcbd442229b6c23304f8021cba45c564f5973701bf215c`。

隔离 Cylinder 候选 SHA：`36fd7c1e7d3aed549d39778673180da5ac765447ba2b8d792d35efe1e367d31c`。

仅替换 Cylinder 中间向量为同顺序标量表达式，保持求根、帽面、边界及相等距离命中顺序。离线实际 Lua 5.4：60019 直接用例、5000 实际 Cast 消费者、12 个混合命中场景，157311 检查、5 个负控通过。离线等价只允许进入性能测试，不代表应该合入。

## 4. 正常 GC ABBA 实测

root 串行运行四个独立 Native 进程，顺序 A1、B1、B2、A2。A 原版，B 仅 Cylinder 候选；每进程 120 步预热后测 240 个固定步。全程正常自动 GC，禁止 collect/stop/mode；主基准没有逐方法计时包装，单步外记录统计和完整快照。

| 轮次 | 总模拟墙钟 ms | 平均 ms/步 | P95 | P99 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A1 | 872 | 3.6333 | 8 | 12 | 17 |
| B1 | 885 | 3.6875 | 8 | 11 | 13 |
| B2 | 873 | 3.6375 | 8 | 9 | 14 |
| A2 | 886 | 3.6917 | 8 | 11 | 16 |

原版均值与候选均值均为 `3.6625 ms/步`，收益 `0%`；原版两次漂移约 1.59%，候选漂移约 1.37%。不能拿单次最大值 17→13 ms 称优化，因为这不是稳定的峰值或完整游戏帧。

四轮每一步都保留八台存活车辆；各轮测量区间均 233 次发射、227 次命中、2050 伤害。初始状态、每 60 步完整八车状态、每步 alive/parts/shots/hits/damage、结束后 16 个 RNG 结果精确相同。独立分析器通过，Native 错误 0、进程退出 0。未降低数量、射线频率、物理频率或更改游戏规则。

本夹具执行完整驾驶/武器/AI/Bullet，但没有图形、音频、UI、BattleController 目标规则及 FX 消费者；不能将 3.66 ms 倒算成游戏 FPS，也不能拿它替代有额外监控的实际八车 Web `26.58 FPS` 记录。后者含持续渲染特效、环境、玩家视角、目标逻辑及不同运行时，未做匹配 A/B。

## 5. 决定与证据

**REJECTED_FOR_PRODUCTION / NO_MEASURED_CPU_GAIN。** 本轮没有把该候选合入，不再重复运行它。持续战斗仍需按实际 Web 分段定位与长帧采样推进；骁龙 845/TapTap 持续 30 FPS 仍 OPEN。
