# 坠舰陨坑浮尘 GPU 迁移（2026-10-06）

来源是只读 H5 的 `three/src/terrain/dust.js` 和 `battle/craterWorld.js`。网页原本就在顶点 Shader 中计算 1600 个粒子的顺风漂移、上下浮动、镜头周围循环、距离淡出和迎光亮度。此前 UrhoX 版本把这些公式放到了 Lua 中，每帧重建并提交粒子顶点。

## 当前实现

- `render/CraterDust.lua` 只在创建时上传 1600 个粒子的种子网格；位置/随机值保留浮点精度。`Crater/Mote.shader` 按原公式生成朝向相机的四边形，镜头 FOV 与源点精灵的像素尺寸换算保持一致。
- 粒子节点随相机移动；两个零面积三角形扩展本地包围盒，覆盖 Shader 位移及四边形半径，避免传送或旋转后被 CPU 错误剔除。1600 粒子总计 9606 个静态顶点，不再每帧提交粒子几何。
- 26 条贴地风沙只有需要重新布点时才重建几何，噪声仍在 Shader 中动画。没有合适落点的条带保持隐藏，直到镜头离开该区域后再尝试；避免原先失败时每帧重复地形/AO 查询。
- 烟柱/尘卷复用角点常量，移除了每个粒子每帧创建的六张角点表；烟柱和尘卷本身仍使用 CPU 顶点更新，不能宣称全部特效已改为 GPU。
- `compile-crater-effects.py` 同步产生正式 Shader，再转换不会覆盖回旧的 CPU 版本。原始 H5 目录未改写。

## 实测证据

同一 Windows Runtime、相同随机种子/相机，测量生产 `CraterDust:Update()`；100 组采样，计时期间停止 Lua GC，以堆增量衡量临时 Lua 分配。优化前每组 4 次调用，优化后每组 256 次，以克服 `os.clock()` 的毫秒粒度。它测的是批次摊销 CPU 开销，不包含 GPU 完成时间、整个游戏帧时或 GC 回收停顿。

| 指标 | 旧 CPU 版 | 当前 GPU 版 |
|---|---:|---:|
| CPU 更新中位数 | 4.50 ms | 0.00391 ms |
| CPU 更新 P95 | 4.50 ms | 0.00391 ms |
| Lua 临时分配中位数 | 350.805 KiB/次 | 0.125 KiB/次 |
| Lua 临时分配 P95 | 353.266 KiB/次 | 0.125 KiB/次 |

证据：`evidence/crater-dust-{baseline,gpu}-metrics.json`。原始 CPU 基线在替换前捕获，当前验证命令只重写 GPU 结果，不再保留另一套废弃的产品实现。

`verify-crater-dust.ps1` 12/12：真实 Shader 绘制、三组截图、完整采样、静态粒子缓冲、传送后包围盒随镜头移动，以及静止镜头更新不调用几何上传。`compare-crater-dust.py` 对比原位置、传送/转向、257 秒循环后的粒子专用画面，检查前景像素，避免背景掩盖特效消失。三组前景平均通道误差分别约 0.63/0.69/0.59（0–255），总 RGB 误差约 3.02%/1.27%/2.63%。旧版把透明度与迎光值量化为 8 位顶点色，新版使用浮点 varying，因此不是逐像素相等。

该对照证明此次 CPU→GPU 迁移与此前原生效果接近，**不证明完整 H5 画面已一模一样**。地图实际进入/驾驶/镜头/传送/返回回归 33/33，运行期错误为 0。

新 Shader 已进入 PC 发布缓存，替代旧浮尘程序；隔离完整开发缓存后，大厅探针 3/3、地图流程 33/33 通过，无新增编译文件。当前 431 个二进制、3,620,235 字节。冷缓存地图流程最大帧约 378.43 ms，仍包含载入等开销，并非持续帧率结论。

## 复现与边界

1. `powershell -File tools/migration/verify-crater-dust.ps1`
2. `python tools/migration/compare-crater-dust.py`
3. `powershell -File tools/migration/verify-crater-game.ps1`
4. Shader 变更后重新收录并隔离验证 PC 缓存，详见 `PC_SHADER_CACHE.md`。

粒子数量、风速、距离淡出与场景风沙保留。GPU 现在对固定粒子网格执行顶点计算，不能仅凭 CPU 数字推断骁龙 845 总帧率、GPU 带宽或温度。真实移动设备、完整场景持续帧时、烟柱/尘卷和地图纹理显存仍需后续验收。当前 UI 仍是 PC 横屏优先。
