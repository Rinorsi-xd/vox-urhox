# 渲染目标生命周期修复（2026-10-06）

陨坑返回大厅、启停后处理及动态分辨率重建时，旧代码直接 Dispose 纹理。Runtime 20260923 的 RenderSurface 保存父 Texture 的原生指针；Lua 借用对象可能在父纹理销毁之后才被垃圾回收。原生栈显示 RenderSurface 析构通过已失效的父纹理查找 Graphics，再发生访问异常。测试使用隐藏窗口，异常对话框表现为卡住，最后由测试 watchdog 结束自己的 Runtime。此前字体/GPUObject 析构栈也观察到异常，不能仅据无符号栈认定每个历史崩溃都是同一原因。

修复在 `scripts/render/RenderTargetLifetime.lua`：退出渲染的纹理先解除视口，进入短暂退役队列；队列强持有父纹理、弱观察借用的 RenderSurface。先执行垃圾回收，确认表面借用已消失，再 Dispose 父纹理。若还有使用者则保留父纹理，后续继续检查。应用正常更新和退出负责排空；没有禁用 GC，也没有永久保留旧地图。FilterGraph、大厅反射、面板和蓝图预览共用这一规则。切换画面时先替换 renderer 的输出视口，再释放旧图。

完整地图测试新增三项检查：持有 RenderSurface 时父纹理在 GC 后仍有效；释放借用后退役目标真正回收；地图退出时退役队列为零，同时原地图模型不在资源缓存中。测试仍覆盖模式卡片的 UI 指针路由、驾驶、九个区域落地、鼠标视角、滤镜启停、动态分辨率缩放/恢复和返回原试车场。

两次连续隔离开发缓存运行通过：首次大厅 3/3、画质 45/45、地图 58/58；再次大厅 3/3、地图 58/58。两次均无新增 shader 编译文件、无运行期 Lua/资源/引擎错误。地图最大帧分别 379.76 ms 和 430.05 ms，不代表稳定 60 FPS。28 级滤镜同帧 HDR 传播回归 35/35，蓝图预览缓存生命周期回归 37/37。记录见 `evidence/crater-rebuild-recheck.json`，原生栈见 `evidence/crater-native-exception-stack.txt`。

没有操作用户编辑器或现有游戏进程。测试范围是当前 PC DX11 Runtime，不能据此宣称编辑器历史崩溃、其他后端、长期运行和移动端性能均已验证。缓存隔离脚本现在在开始/失败时也写入状态，避免异常后继续留下旧的成功报告。
