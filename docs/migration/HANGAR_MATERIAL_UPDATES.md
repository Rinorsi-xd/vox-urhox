# 大厅材质时间更新与灯光差异

来源基线：`2026-10-13 / 90862445074e7e146da900037979ad97899ecf6c`，只读冻结快照。Web 构建：`outgame-cached-1791874673332 / manifest-b58be5df.json`。本轮没有改场景灯光数值、材质着色或页面构图。

## 已实现的 CPU 优化

以前每帧为大厅全部 98 份场景材质创建 Variant、写入 `hangar_time`。其中墙面、地板、无闪烁灯带等并不使用时间。现在保留全部场景克隆和共享关系，只更新 22 份有动画的材质，每帧只创建一份时间 Variant；固定调试时间不重复写入。时间回退仍会更新。

`Surface.shader` 按 `uPulse/uBlink` 判断，`Glow.shader` 按 `blink_rate` 判断。已审查的 Decal、Deck、Glass、Guide、Sign 不更新时间；Beam、Boundary、Curtain、Dust、Holo、Scan、Space 保留更新。未知 shader 保留旧更新行为，避免未来新增材质的动画被静默停掉。改变上述参数需通过现有场景重载重新绑定；目前没有运行时修改这些脉冲参数的业务路径。

原生 `verify-hangar.ps1` 54/54 通过，报告 `evidence/validate.json`，报告内 Lua/资源/引擎错误为 0。新增检查覆盖全息屏、GPU 尘埃、外景、静态车台时间不变、所有动画材质的时间写入和调试时间回退。启动 stderr 仍有历史 `DaySpecularHDR.dds` 和 `themis_x64.dll` 错误，不称整份日志零错误。

同一 Windows Runtime 内交替比较旧路径和新路径，五轮各 2000 次更新，测试前 GC，使用现有 Profiler 相同的 `os.clock()`。每对计时分散在独立帧，保留 500 ms 卡顿门槛。结果为 `evidence/hangar-material-update.json`：

| 路径 | 2000 次的中位时间 | 每次更新 |
|---|---:|---:|
| 旧：98 份材质，各自构造 Variant | 215 ms | 0.1075 ms |
| 新：22 份动画材质，共用 Variant | 25 ms | 0.0125 ms |

每帧局部节省约 0.095 ms，时间参数写入减少 77.6%。这不是整体帧率提高 88%，也不能解决大厅上千绘制批次和 GPU 成本。本轮未测真 M1 或手机热稳定表现。测试辅助代码初次使用 `Time:GetSystemTime()` 遇到旧运行时静态绑定差异，改用已有计时方式后通过；初次把全部测量放进一帧触发 1654 ms 卡顿，现已分帧，未放宽门槛。

## Web 画面回归

`capture-hangar-parity.cjs` 覆盖 PC 1920×1080、20:9 横屏 840×378、4:3 横屏 1024×768，源与目标时间 10、相机、车台参数、209 个零件和六个世界锚点一致。每端运行错误为 0，锚点最大误差小于 0.00013 像素。报告 `evidence/hangar-fixed-parity.json` 包含实际构建身份和材质计数 98/22。

三端截图均已检查；中央 3D 区域像素标准差各 RGB 通道约 48–53，确认不是空画面。手机版截图 2520×1134、平板 3072×2304 为 DPR=3 的物理尺寸，并非竖屏适配。源/目标截图为 `evidence/hangar-fixed-{source,web}-{pc,phone-landscape,tablet}.png`。

每端仍有四条本地引擎镜像聚合包 HTTP 404，随后逐文件成功加载，记录在报告 `httpErrors`。没有把 HTTP 404 混同为零错误请求。当前对照用于相机和画面回归，不证明整页像素相同。

## 尚未修复的灯光差异

冻结源 `shared/scene/hangarLayout.js:973` 主聚光灯为 `intensity=3.15, decay=0`，迁移场景仍为 `brightness=1650`。这两者在约 23 米距离接近，但高车体靠近灯时，迁移版仍会变亮，原版不会。

已读 Light API、SurfaceShader 示例及此前导出的 Runtime 灯光 shader：PBR 点光/聚光固定使用距离平方衰减和范围遮罩，Light 绑定没有衰减指数入口。普通 `rampTexture` 没有接入这条 PBR 衰减路径。直接改成 3.15 会把实际光照强度再除以距离平方；调整曝光会同时改坏其他面光和自发光。

当前自定义 `light()` 路径处理点光/聚光，但没有保留原 PBR 路径的矩形面光积分。贸然替换所有实体材质会损失大厅四盏面光和清漆高光，因此本轮没有交付这种替换。后续需要验证引擎侧可配置衰减，或为聚光和矩形面光完整实现并验证源 BRDF；阴影、清漆和移动端成本都必须一起验收。这个差异保持未完成状态。

固定相机截图仍可见原 H5 与 UrhoX 的泛光、玻璃、车台反射及正文栅格差异。材质更新优化不改变这些差异，不作为大厅光照复刻完成的证据。
