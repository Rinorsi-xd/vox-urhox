# 原版装饰动画补齐

来源为只读 H5 的 `three/src/parts/materials.js`。此前 `holoPaint` 被归为普通 PBR 发光，`spinSteel/spinGlow/glowBlink` 只导入了静态材质参数，丢失原版 shader 和 updateMaterials 动画。

现在全息徽标使用源颜色的加色叠加、双面、不写深度、不投影；每秒 0.8 弧度绕零件安装轴旋转，并保留本地高度扫描线、31/7 Hz 闪烁和视角边缘亮度。普通/大型徽标都使用同一材质，实例颜色负责涂装，不创建每件私有材质。

雷达盘金属/发光部分按源 0.9 弧度/秒一起转动，底座不转；法线与顶点一起旋转。源几何在导出时镜像 X，因此 shader 旋转正弦符号做相应转换。只有 spinSteel 为双面，其余 PBR 发光材质保留背面剔除。剔除规则写进独立 shader 壳，热重载时不会丢失 Lua 临时覆盖。

信号灯以源 `fract(t*0.9)<0.14` 在 6 与 0.25 强度间切换；青色/绿色灯条恢复 `2.4 + (0.5+0.5*sin(t*1.1))*幅度`，幅度分别为 0.5 和 0.4。所有动画直接使用 GPU 时间，没有增加逐零件 Update、定时器或材质克隆。`animation_time` 默认 -1 使用引擎时间，专项截图覆盖它以固定时间采样，结束恢复默认。

PartAssets.Model 在加载旋转材质对应的共享模型时一次性扩大 X/Z 包围盒，覆盖整圈旋转；不会改动网格、碰撞和装配元数据。弱键表记录已处理的模型/包围盒；重复绑定不累积膨胀，资源重载恢复原包围盒后可以重新计算。资源仍由现有 VehicleView/PartAssets 生命周期释放。

`verify-decor-motion.ps1` 在隐藏独立 Runtime 中渲染八个真实导入模型，检查共享材质、独立涂装、阴影、旋转范围、反复绑定和释放；固定 0、0.4、1.95 秒采样，1.95 秒重复帧用于稳定性检查。`decor-evidence.py` 逐区域确认徽标/雷达/灯发生可见变化，重复固定帧没有超过 2 色阶的像素差，输出 `evidence/decor-motion-comparison.png` 与来源/目标哈希。该结果不证明完整 H5 像素一致或真机性能。

大厅中穿过车身的竖直条纹平面来自源 welcome 入库扫描，约 2.2 秒结束。它并非静态废案，本轮没有因首页截图截到它而删除。

当前全目录对照已发现新的源数据差异和启动帧尖峰，详见 CURRENT_SOURCE_DRIFT.md；不能用装饰专项验证替代全量同步和性能验收。

最终 shader 文件缓存后的复跑为 43/43，通过且零 Lua/资源/引擎错误；0→1.95 秒的徽标、雷达、信号灯区域均有可见像素变化，1.95 秒重复帧差异为 0。首次加载 23.0 秒尖峰的失败报告仍独立保留；尚不能称为冷启动性能通过。
