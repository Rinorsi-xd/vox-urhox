# 靶车破坏迁移（2026-10-05）

试车场已接入原版三辆靶车、逐零件生命值、穿透、断连脱落、物理残骸和五秒重生。使用同一 TrialSession；源工程保持只读。源玩家车当前不受伤，本轮没有另加玩家伤害规则。

## 规则与职责

- `combat/CarUnit.lua` 保存临时战斗蓝图和生命值。核心毁坏或剩余预算低于初始的 30% 判定报废；断开的连通组各自成为残骸。损坏不修改用户保存的蓝图。
- `build/Blueprint.lua` 使用 4×4×4 实体子格掩码定位受损零件。首段查找、下一零件穿透和爆炸遮挡沿用源规则；爆炸接口已有源回放验证，不等于新增可操作爆炸武器。
- 移除零件后重新计算质量、载重、悬挂和控制配置，重建刚体时保留变换、线速度、角速度和控制状态。显示复用剩余关节实例，避免出现完整旧车与新车叠加。
- `combat/VehicleRay.lua` 为复合碰撞体补充零件归属查询，包含盒、旋转体、车轮和履带感应体；先查局部总包围盒，再查具体形状。原生地图遮挡仍参与最近命中比较。
- `combat/Debris.lua` 管理有质量、有碰撞、可受射击冲量的连通残骸；存活五秒，最多 60 组，超限优先释放最旧组。使用统一世界时间，在重生和物理步之前移除到期残骸。
- `render/CombatView.lua` 消费生成、移除、重建和死亡事件；显示插值不回写模拟。残骸最后 0.6 秒缩小，退出场景清空节点与事件。
- `render/ChipEffects.lua` 生成沿用源颜色、重力、反弹和旋转的视觉碎屑；mobile 最多 96、desktop 最多 360 个，惰性创建并复用。视觉碎屑不承担伤害或物理碰撞判定。

## 重生时序修复

原先残骸在物理步之后累计年龄并释放，靶车在物理步之前按世界时间重生。两个计时方式的浮点差异使旧残骸多存在一至两个碰撞步，实测新车重生首步收到异常角速度，偶发翻车并导致射击回归失败。

现在残骸出生时间与死亡时间使用同一模拟时钟；到期清理先于重生，物理步后只采集显示姿态。回归故意把旧残骸放回重生位置，检查首步没有残骸/角冲量、随后保持直立、原位和静止，不靠随机残骸飞离来通过。

## 验证

`source-damage-fixtures.mjs` 只读执行原版模块，记录来源哈希，生成七组伤害/脱落/报废/重生回放、96 组旋转实体掩码（6144 点），以及原版 Rapier 0.21.0 实际车辆碰撞体的 1080 条射线。射线对照覆盖赛车、坦克和三个偏航角，比较最近表面距离和允许的等距零件 ID。

```powershell
./tools/migration/verify-destruction.ps1 -Quality mobile -Screenshot
./tools/migration/verify-destruction.ps1 -Phase damaged -Screenshot
./tools/migration/verify-destruction.ps1 -Phase wreck -Screenshot
```

mobile 与 desktop damaged 各 7918 项；desktop wreck 7919 项，包括实际安装武器连续射穿装甲、摧毁核心。检查还覆盖车轮移除、刚体质量变化、状态保持、残骸运动/冲量/过期、容量限制和返回大厅释放。报告和画面位于 `evidence/destruction-*.json`、`evidence/current-destruction-*.png`。

## 边界

Bullet 的质心/惯量与源 Rapier 不同，碰撞轨迹不保证完全一致；旋转 hull 当前用对应旋转盒适配。源伤害回放和射线对照不替代原生运动验证。节足移动未实现；悬浮/飞行的原生检查与差异见 AIR_DRIVE_MIGRATION.md。

常驻装备效果、部分高级武器火花/电弧、闪光点灯、声音/震动、完整 GUI 与伤害统计界面仍未同步。当前 mobile 档在电脑运行，不是骁龙 845 真机持续帧率/温度验收。编辑器原生崩溃仍未定位，本轮没有操作编辑器。
