# Web 持续交火：堆变化与长调用的只读归因

日期：2026-10-17。状态：`OBSERVATION_ONLY / ROOT_CAUSE_OPEN`。

## 结论

首伤缓存复用后的实际 Web 对局仍有持续负载和长帧。现有完整帧记录中，较长的单次 AI、腿步态、悬挂和特效调用都与较大的 Lua 堆下降同帧出现；承担长墙钟的范围分散，不能据此直接把 AI 或腿算法判为唯一瓶颈。

此结果支持优先细分分配和自动回收相关成本，但**不证明回收的准确耗时或触发源**。监控本身的分配也包含在当前堆记录中。此报告没有运行新的游戏、修改生产或原始证据，也没有宣称帧率优化通过。

## 数据与计算

输入是已经由主 agent 完成的 `evidence/monitor-combat-adopt-2a92-a/` 实际八车交火。沿用该报告的完整帧对齐，共 1371 帧、45051 ms，实际开火、受伤和结构破坏存在。此处只读计算相邻完整帧的 `luaKiB` 差及已有阶段统计。

| 观察量 | 结果 |
| --- | ---: |
| 平均帧间隔 | 32.860 ms |
| Lua 堆开始 / 结束 / 最大 | 81.539 / 111.330 / 115.649 MiB |
| 相邻帧正向净变化累计 | 2131.657 MiB |
| 正向净变化累计 / 45.051 秒 | 47.317 MiB/s |
| 相邻帧反向净变化累计绝对值 | 2101.866 MiB |
| 堆下降超过 10 MiB 的完整帧 | 145 帧 |
| 这 145 帧平均帧间隔 | 60.303 ms |
| 其余完整帧平均帧间隔 | 29.614 ms |

正向净变化定义为 `sum(max(0, heap[i] - heap[i-1]))`，反向变化对应负差的绝对值。这是采样之间的净堆变化，不是 allocator 的逐次分配记录，不包含期间已分配又释放而未跨帧留下的全部对象，也不能把 47.317 MiB/s 直接当作生产玩法的准确分配速率。
