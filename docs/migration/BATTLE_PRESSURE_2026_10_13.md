# 战斗压力与特效分配

迁移现场已保存为私有 GitHub 仓库 `Rinorsi-xd/vox-urhox` 的 `codex/h5-2026-10-13`，备份提交 `57c414d`。以下比较引用该提交的 `EffectBatch:Segment/Disc` 精确旧公式，参考实现只存在工具脚本，不进入发布脚本。

## 特效分配优化

共享 `EffectBatch` 的光带/圆片改为每批次复用四个顶点、四个 UV 和三个着色参数的 Lua 表。归一化/叉积使用相同标量公式，不减少粒子数量、不改 shader、颜色、宽度或射击参数。空向量、相机平行向量、零宽度、streak 尖端和 core=0 均有实际 GPU 顶点对照。

生产场景中的 100 个光带 + 100 个圆片，1200 顶点位置/法线/UV/颜色全部与旧公式误差小于 .0001。独立 40 轮、每轮 60 圆片+60光带、停止 GC 只测当前批次临时分配：旧公式中位 243.445 KiB，优化公式 9.539 KiB，减少约 96.1%。此微基准不包括构造时的 scratch 表；不是整场游戏内存降低 96%，也不是帧率提高 96%。CPU 采样约 1ms，Windows `os.clock` 分辨率较粗，不据此承诺 CPU 倍数。

## 原生压力范围

生产争夺战 4V4，真实车辆、AI、武器、物理、损毁/复活，固定步 1800 次即 30s 模拟时间，主动把车辆放近交火以产生压力。旧公式与优化公式分别打出 2094/1974 次射击，峰值粒子 236/235、弹丸 10/12，特效未超生产上限；返回时两组地形数组释放为 0。

两场交火结果不确定且负载不同，整场 tick/AI 时间不能直接用于收益百分比。`ai` 包裹整个 BeforeStep，包含武器逻辑，不是独立纯 AI 成本。截图可见侧翻车辆与近距离车辆互相推挤，不把这次测试说成 AI 从不卡住。

早期报告的 frameMs 全是 16.6667ms，来自验证模式的固定 TimeStep，是合成时间，不能当成实测 60FPS。工具改为相邻 Poll 墙钟间隔，包含测试和渲染开销；后续报告以 scope 字段为准。当前原生静态绑定实际必须使用 `Time:GetSystemTime()`；曾用 `time:GetSystemTime()` 的 optimized-wall 运行失败，不能采用。接口差异已用独立运行探针确认，文档/类型声明的实例调用示例与本运行器不一致。网页探针在真实非验证循环中采集 TimeStep，并记录 fixedSteps/droppedSeconds、绘制调用、图元、资源和特效数。

这些是 Windows 桌面证据。真实 M1/手机的持续帧率、冷热下载、发热和内存仍未验收。当前仍有约百万级图元和较多绘制调用、CPU 特效/寻路负担；不能承诺 M1 或手机稳定 60 帧。后处理、LOD、遮挡、shader 冷启动和持久化还需继续完成。

## 修正计时后的压力结果

`battle-stress-mobile-optimized-wall.json` 8/8 PASS，测试窗口 Lua、资源和引擎错误均为 0；指标在同名 `-metrics.json`。1800 次真实固定步、30 秒模拟时间，1799 次墙钟间隔 P50/P95/P99/max 为 34/63/74/105 ms。移动质量档本来限制 30 FPS；墙钟间隔还包含验证器开销，不能从它推导 M1/手机帧率，也不能称稳定 60 FPS。

最后采样为 8 辆存活、2132 次射击、740 绘制批次、约 328 万图元，资源缓存约 221 MiB，两组数组约 64 MiB。峰值粒子 238、当前玩家弹丸 13。Tick CPU P50/P95 为 19/53 ms，包含武器的 BeforeStep 为 5/38 ms，特效更新 4/5 ms、物理 1/2 ms；Windows `os.clock` 精度限制与 GC 干扰均存在。这个结果说明仍有帧时间尖峰，不能把临时分配优化误报为整场流畅验收。独立批次分配中位仍为 9.539 KiB。

## 网页持续交火：流畅度未通过

`outgame-cached-1791907814238 / manifest-ebf8980e.json`，Windows Chrome D3D11、840×378 横屏触控、DPR 3，生产 4V4 争夺战持续 60 秒。报告 `evidence/battle-pressure-web-phone-landscape.json` 的 15 项 PASS 只指加载、开场、AI、捕获点和退出释放的流程断言；**性能验收失败**。

外部 requestAnimationFrame 墙钟采样在前 3～22 秒的窗口 P50 为 41.4～62.1 ms，末尾 57～60 秒为 118.1～118.3 ms，最大两次间隔 555.7/534.9 ms。约 1245 批次、568 万图元增长到约 1948 批次、712 万图元，资源缓存 202.1→203.9 MiB，Lua 堆在 45.6～56.6 MiB 间波动。这些数据尚不能归因为碎片或资源泄漏，地图可见量和交火负载也会变化，需独立定位。

引擎 TimeStep 采样最多约 100 ms，`performance.droppedSeconds` 末值仅约 5.1e-8 秒，不能反映外部超过 500 ms 的停顿。因此后续性能判断必须同时保留外部 rAF 墙钟。不是手机/M1 实测，也不据此声称迁移已流畅。
