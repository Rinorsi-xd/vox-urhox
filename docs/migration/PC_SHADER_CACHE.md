## 对照与结果

默认缓存目录由引擎返回 `shadercache_runtime/`；本机可写缓存位于 `.cli/ResCache/shadercache_runtime/dx11`。引擎同时从项目资源根查找同名编译二进制。因此把已验证的缓存放入 `assets/shadercache_runtime/dx11`，即可沿用默认加载，不改游戏 Lua 的缓存路径、不关灯光/阴影、不改变 shader 源码。

- 隔离雷达相关本机缓存、保留项目缓存：3 项断言通过，最大帧时 228.4 ms，没有重新生成雷达缓存。
- 只移走项目中的目标像素二进制：3 项功能断言通过，但整体验证失败，重现 22093.95 ms 单帧阻塞。证据 `evidence/shader-without-radar-binary.json`。
- 恢复目标二进制，其 SHA256 与重新编译结果相同：`dfe97ace99587e091b36924d0dd1a278b21a69deb4f16d08ebdf722b5bf3fce0`。
- 隔离整个本机 DX11 缓存，只使用项目缓存：探针 3 项与建造菜单 56 项通过，首次完整对照最大帧时分别为 224.84 / 247.47 ms；没有新生成的缓存文件。后续最新复测见 `evidence/pc-shader-cache-isolation.json`。

这只消除了已测路径的约 22 秒冷编译，约 250 ms 的最大帧仍不代表稳定 60 FPS。

## PC 构建前流程

1. 使用准备发布的 Runtime/资源包，运行首页、蓝图窗口、建造及需要覆盖的场景验证，取得实际载入的 shader 日志。
2. `python tools/migration/stage-pc-shader-cache.py --logs <项目内日志路径...>`。默认输入为首页、建造菜单和雷达探针日志。它按出现的程序名收集已编译变体，保存输入日志快照、引擎/源码/二进制哈希并删除清单中不再需要的旧条目。
3. 构建前执行 `python tools/migration/stage-pc-shader-cache.py --check`。引擎或 shader 源变化、文件缺失或哈希错误都会失败，必须重新生成并验证；此工具尚未自动挂入编辑器发布按钮。
4. `./tools/migration/verify-pc-shader-cache.ps1 -Python <Python路径> -FullMenus` 可临时隔离整个开发缓存并运行实际入口及菜单往返；`-Graphics` 运行 PC 画面设置、曝光和真实试车往返，两开关可组合。退出时恢复原缓存，失败时保留新生成文件供补齐覆盖范围。要求零新编译、零错误及最大帧时小于 2 秒。
5. PC 包包含 `assets/shadercache_runtime/dx11`。当前清单 557 个二进制，总计 4,314,106 字节，收录已测大厅、地图、车辆、武器与菜单路径；不要把 `.cli/ResCache` 或 `.tmp` 打包。具体本轮重跑范围以顶部记录为准。

当前验证版本 `20260923-1717-bf3316f`，commit `bf3316fd21de510af2fec2a9df99d476536f1b1e`，引擎资源 `maker_validate_window.0923`。项目仍配置 latest，缓存清单的哈希检查用于检测更新，不等于已锁定发布渠道版本。
