## 散布材质遗漏

原转换已经保存六张法线 PNG 并写入八份材质，但旧 Scatter.shader 没有声明/采样 `normal_map`，岩石和灌木仅使用模型顶点法线。现在恢复原贴图和 `normalScale`，保留原 UV、镂空阈值和双面绘制。

源 props GLB 全部没有 TANGENT 属性，Three r186 使用 UV 导数构造切线。`ScatterNormal.shaderinc` 采用相同的导数框架，显式处理反射 X 坐标、屏幕 Y 方向和背面法线，不依赖转换模型中不存在的切线。该修改没有重新生成美术素材。

- `restore-crater-scatter.py` 从原六个 GLB 恢复八种材质的 normalScale，并记录源哈希。所有当前源材质强度均为 (1,1)，不是凭外观调参。再转换已由浏览器导出器保存该值。
- `check-crater-normal.mjs`：240 个正反面、镜像 UV、屏幕 Y 翻转及不等长导数组合，与 Three 原公式的双精度计算误差为 0。这是数学验证，不代替 GPU 验证。
- `verify-crater-scatter.ps1`：八份实际材质绑定和四张实际模型渲染共 12/12，无引擎/资源/Lua 错误。
- `compare-crater-scatter.py`：固定灯光下仅切换法线强度，岩石 72,717 像素、叶片 17,556 像素发生大于 1/255 的变化。已检查 `evidence/crater-scatter-normal-comparison.png`。

恢复贴图必然增加真实纹理驻留；不能把遗漏贴图当成性能优化。此项不代表整个 Three PBR/IBL 已逐像素一致。

## 模型数据

`crater-model.cjs` 是导出器和离线优化器共用的 UMDL 处理器。只支持当前明确的单顶点缓冲/单索引缓冲/单几何/无骨骼布局；遇到其他布局立即报错。

以完整 44 字节顶点记录去重，保留法线、颜色、UV 和 UV2 接缝、三角形顺序/绕序及包围盒。唯一顶点数不超过 65,536 时使用 16 位索引，否则保持 32 位。

300 个模型从 70,519,120 降到 62,787,290 字节，减少 **7,731,830 字节（约 7.37 MiB，10.96%）**。不是降低几何精度，也不声称这个数就是 GPU 显存收益。

`optimize-crater-models.cjs --apply` 在第一次写入前验证整批模型的逐三角形展开字节 SHA256 和尾部元数据，单文件使用临时文件原子替换。完整证据：`evidence/crater-model-optimization.json`。边界验证覆盖 65,536/65,537 顶点、UV 接缝、重复顶点、非法索引和幂等性。后续浏览器重新导出自动使用同一个优化器。

## 驻留限制

**后续已修复天空保留，并将建筑烘焙图无损打包为 RG8 KTX。** 最新状态见 `CRATER_RESOURCE_RESIDENCY.md`；下述 3/6 结果是修复前基线，保留用于对照。

当前 Runtime 的 Texture2D.memoryUse 返回 0，资源缓存总数不是总显存。两组 2048²×6 地形数组实测合计 256 MiB，原始 PNG 加载时没有使用 sidecar 声明的 GPU 压缩。退出地图后三轮均仍发现 `Crater/Sky.hdr`，完整卸载断言仍失败；不能声称所有地图纹理已释放，也不能仅凭三轮平台值认定无长期泄漏。
