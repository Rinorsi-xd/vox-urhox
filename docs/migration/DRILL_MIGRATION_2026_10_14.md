# 钻头武器与战斗反馈迁移

## 来源与范围

来源为冻结 H5 分支 `2026-10-13`、提交 `90862445074e7e146da900037979ad97899ecf6c`，只读 `.tmp/outgame-source-2026-10-12T21-18-23-463Z`；没有读取正在修改的源工作区。目标分支 `codex/h5-2026-10-13`。未调整场景光照、添加新 UI 风格或导入废弃主按钮流光；无尽仍排除。

本批修复“钻头模型已迁入，但武器导出只收录远程武器”的功能断层。`Combat/Weapons.json` 现在包含 17 种原武器；`Combat/Drills.json` 的五层刀片截面由原 `drillData.js` 导出。

## 实际接入

- 天元：按住蓄力、松开突进、低蓄力取消、维持耗能、能量耗尽自动释放、六次切削、钻穿推动及共享冷却。
- 夫元：原五球扫掠、碰撞咬合、车体绕钻尖旋转、刀片反转、甩出及冷却。
- 原准星蓄力/突进/咬住/冷却反馈，原钻头图标复用规则、冲击/碎屑/烟尘与蓝/粉速度线；保留现有相机基础行为，接入原钻头 FOV 增量。
- 实际原生车辆与零件伤害、履带/机甲质量为零的命中传感器、目标护盾/反应堆规则。试车、竞技、剧情与打捞共用同一攻击模块。
- 钻头占用刚体时停止普通驱动、腿部支撑和转轴输入；暂停、翻车、传送、受损重建、退出先取消并恢复动态属性和原 CCD 参数。

`DrillSweep` 使用原生凸形扫掠，重用五个查询形状和传感器池；排除自身及无关触发器，跳过支持地面，并在查询成功或失败后恢复碰撞层。引擎实际测试确认 `collisionMask=0` 会使查询也忽略传感器，因此采用隔离的 `0x4000` 层，查询结束恢复到 layer 0。

速度线仅在首次突进时创建一个全屏叠加 draw，不分配离屏颜色/深度纹理，不在 CPU 重建粒子网格；暂停立即隐藏，退出恢复原 viewport 数量。原 `blend_add` 接法曾产生过亮白线，最终用预乘混合、零目标衰减与原颜色强度一次相乘修复；网页冻结同一状态开关叠加图层，验证实际 canvas 像素差异，而非只检查 visible 标志。

## 剩余边界

本批不是整项迁移完成。完整源触屏交互、转轴镜像盘面、翼面/新版机甲控制、MVP/开篇签约演出、其他页面背景模糊与剩余 UI 反馈、正式账号云存档刷新恢复及跨设备冲突仍需完成。原完整速度 FOV 系统也不能由本批钻头增量证明已全部对齐。

扫掠微测在本机 120 次单截面调用/240 次原生 cast、一个传感器下合计约 3ms，只是局部开销数据；不代表八车战斗、真手机或 M1 的持续帧率。大地图 LOD、空间拆分、长期 AI 行驶、冷下载、真机发热与内存仍需实测。未上传、提审或发布 Maker。
