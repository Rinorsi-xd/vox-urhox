# 移动端性能与加载约束

最新：天空烘焙缓存的跨场景持有已清理，并增加候选场景光照就绪门禁；五张建筑图无损 RG8 KTX 使纹理有效载荷从 154.67 降到 58 MiB。普通 Texture2D 的统计限制、地形数组压缩阻碍、文件体积增加和真机边界见 `CRATER_RESOURCE_RESIDENCY.md`。下文天空卸载失败是已被修复的基线结果。

2026-10-06 后续测量：地图模型无损精简约 7.37 MiB；散布法线贴图恢复，不能以遗漏贴图换性能。当前原始 PNG 路径仍未实际 GPU 压缩，两组地形数组合计 256 MiB。Texture2D 的引擎内存统计为 0，因此 cache 总数不能当作总显存；地图退出后天空 HDR 完全卸载检查未通过。详见 `CRATER_SCATTER_AND_MODELS.md`。以下较早测量保留时间与范围，不代表最新资源总量。

目标：骁龙 845 档设备先争取持续稳定 30 FPS。该值是验收目标，不是已达成结论；当前只有 Windows 环境，不能推断手机热稳定表现。

## 调研依据（2026-10-05）

- Android 游戏优化：https://developer.android.com/games/optimize 。减少可见对象与 draw call，跟踪帧时间而非平均 FPS，持续运行后温度可能导致降频。
- Android ADPF：https://developer.android.com/games/optimize/adpf 。以可持续性能为目标；UrhoX Lua 当前没有确认的 ADPF 接口，因此不把它写成已接入能力。
- 顶点数据：https://developer.android.com/games/optimize/vertex-data-management 。顶点布局、带宽、冗余数据会影响 GPU；模型应离线转换并共享，避免启动时 Lua 逐顶点重建。
- 纹理：https://developer.android.com/games/optimize/textures 。mipmap、GPU 压缩、合图分别影响采样、显存、批次。PNG 压缩体积不代表 GPU 占用，后续发布构建必须检查实际设备纹理格式。
- 项目 `engine-docs/recipes/download-while-playing.md` 与 `preload-and-build-refs.md`：使用平台下载与缓存，异步 API 回调。文档中 `.mdl` 同时出现在 blocking 和媒体类型表，不能承诺模型一定可延迟下载；以发布清单和设备请求记录为准。

## 决策

1. 离线把源程序化几何和 GLB 分段转成原生 Model，保留挂点/炮口/关节数据。相同几何内容去重，多材质槽存一个 Model。运行时按车型/目录页引用，不预生成整个目录。
2. CPU 实例化也要分帧。目录每页有限数量，关闭销毁实例；模型由引擎资源缓存共享，清理只释放无引用资源，不强制 Dispose 其他车辆仍在使用的模型。
3. 反射已采用手动更新：移动档 1/4 分辨率、最长边 384、10 Hz；桌面档 1/2 分辨率、最长边 960、30 Hz。移动档阴影 1024、上限 30 FPS。原生零件通过相同顶点焊接由 89,603,164 字节减至 34,293,112 字节；全目录 351 个模型，不代表同时驻留。
4. 主场景与反射都需检查透明叠层、灯光数、阴影距离。特效优先事件驱动、池化、距离裁剪；远处降低更新频率。动画骨架和移动不能合并烘焙进静态建筑。
5. 场景切换成功后卸载旧场景和专属相机、反射 RT、粒子、音效、下载观察者。保留蓝图数据和必要共享资源；异步回调使用代次校验，离场后不得复活节点。
6. 启动仅首屏内容；选车后预取所需部件，进入试车前预取场地与音效。返回大厅释放试车专属实例。开发热加载和发布资源版本更新是两个流程，不做独立自建下载服务。

## 真机验收（尚未执行）

同一档位记录首屏冷/热启动、弱网失败重试、连续切换十次的内存趋势、帧时间 P50/P95/P99、卡顿峰值，以及持续 30 分钟后的温度和帧率。空闲大厅、满配车建造、移动与连续开火分开测。性能门槛需要真机基线后调整，不能以桌面验证报告宣称适配完成。

## 当前证据限制

独立 Runtime 移动质量档零件验证 2798 项通过，这只说明该配置下资源和关节逻辑可用。编辑器 Play 曾显示约 1.36M primitives / 1192 draw calls（含编辑器视图和渲染 pass），渲染成本仍高，不能据此宣称骁龙 845 达标。另有用户报告的编辑器交互原生崩溃待定位。

2026-10-06 PC 地图加载：新增引擎下载就绪门禁、异步场景和分帧碰撞准备，取消/失败/重试检查 23/23 通过。整张坠舰陨坑在被选中后才准备，退出和取消释放未引用模型；物理与视觉共用解析后的高度布局。实测准备 142 帧、最大准备片段 74 ms、全流程最大帧约 405.03 ms；3 ms 是检查点之间的协作式预算，不是硬上限。资源约 247.2 MiB，尚未按地理区块流式加载，远端实际下载/续传也未验证。这些桌面数据不构成移动端性能结论；当前 UI 仅推进 PC 横屏。

同日把原先每帧 Lua 重建的 1600 个浮尘恢复为源网页的 GPU 动画，未减少粒子数量；地面风沙也只在重新布点时更新几何。桌面批次计时中 `CraterDust:Update` 中位从 4.50 ms 降至约 0.00391 ms，临时 Lua 分配从约 350.8 KiB 降至 0.125 KiB/次；这是局部 CPU 测量，不能推导真实移动 GPU/总帧时。种子相同的三组前景截图对照及上传生命周期测试通过，详见 `CRATER_EFFECTS_PERFORMANCE.md`。
